# “出去晃晃”交互原型整屏适配设计

## 目标

在浏览器保持 100% 缩放时，“出去晃晃”交互原型必须完整、等比例地显示在作品集网站的黑色手机框内。用户不再需要按 `Ctrl + 滚轮` 缩小网页。

## 当前问题

外层手机框会根据浏览器可用高度缩小，但嵌入原型内部仍按自身尺寸重新排版。窗口较矮时，外框已经变小，内部页面却没有按照同一比例缩小，因此只能看到局部内容。

## 方案

- 保留网站现有黑色手机框及独立路由 `/experience/wander-ui`。
- 保留原型的设计基准尺寸和宽高比。
- 在 iframe 加载后测量实际可用屏幕宽高，计算 `min(可用宽度 / 设计宽度, 可用高度 / 设计高度)`。
- 将原型根画布按该比例整体缩放并居中，不对内部组件重新排版。
- 浏览器窗口变化、横竖屏变化时重新计算比例。
- 继续隐藏原型自带的第二层设备外壳和设备选择器，确保页面只有一个手机框。
- 只适配网站发布目录中的嵌入副本，不修改用户提供的原始单文件原型。

## 边界与降级

- 不修改“租前眼”和 ClearSense 的原型页面。
- 不改变“出去晃晃”的页面顺序、按钮、动画或交互逻辑。
- 极端窄屏允许手机整体继续缩小，但不能裁切原型内容或产生横向滚动。
- 若脚本无法读取 iframe 尺寸，保留当前可操作页面，不显示空白屏。

## 验收标准

1. 浏览器缩放为 100%，在 1366×768、1440×900、1920×1080 下均能完整看到手机内的首页和底部导航。
2. 手机宽度 360、390、430 像素时界面完整位于手机屏幕内。
3. 选择“想安静一点”后能进入下一步，下一页同样完整适配。
4. “重新开始”能够回到初始页，并继续保持正确比例。
5. 页面只出现一层黑色手机框，无横向溢出、无控制台错误。
