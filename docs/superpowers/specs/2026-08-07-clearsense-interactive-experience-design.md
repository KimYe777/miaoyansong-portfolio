## 4. 3D模型方案

### 转换

- 保留原始 `.3dm` 文件不变。
- 当前版本使用 Three.js 官方 `3DMLoader` 按需读取网页内的 `.3dm` 副本，并保留可分离对象；这是在本机 Rhino/Cinema 4D 无法无界面稳定导出时采用的无损落地方案。
- 模型仅在用户接近互动区域时下载和解析。后续如取得可靠的 `.glb` 导出文件，可在不改变交互界面的前提下替换加载源，以进一步减小体积。
- 移除参考图片平面、重复版本或明显不属于最终产品的场景对象。
- 对模型进行三角面、法线、材质和文件大小检查；在不产生明显外观损失的前提下优化移动端加载。

### 交互

- 鼠标拖动和单指滑动：旋转。
- 鼠标滚轮和双指：缩放。
- `自动旋转`：开关控制，默认关闭。
- `复位视角`：恢复初始相机与缩放。
- `分开 / 合上`：0—100滑杆控制零件从装配位置向外移动。
- 爆炸方向以产品整体中心与每个零件中心的向量为基础，再通过实际渲染人工修正，避免互相穿插。

### 加载与降级

- 3D代码和模型在交互区接近视口时才加载。
- 加载中显示明确的中文状态。
- WebGL不可用、模型加载失败或设备性能不足时显示 ClearSense 静态产品图，并保留说明文字。
- 动效降级模式下不自动旋转，滑杆仍可手动操作。

## 5. UI原型方案

- 将交付目录完整复制到网站静态资源目录，保留原HTML、CSS、JavaScript和图片的相对路径。
- 通过受限 iframe 嵌入，避免原型样式污染作品集网站。
- iframe标题使用中文可访问名称。
- 桌面端同时展示原型界面和原有演示控制。
- 手机端优先显示可操作界面，减少外部装饰和重复设备边框造成的空间浪费。
- 提供“重新开始体验”和“在新窗口打开”入口；新窗口地址同样支持GitHub Pages子路径部署。
- localStorage仅保存原型演示状态，不采集或上传用户数据。

## 6. 视觉与文案

- 延续 `DESIGN.md` 的暖白、墨黑、克制橙色和编辑式编号体系。
- 交互区使用 ClearSense 的冰蓝与森林绿作为局部识别色，不改变全站基础色。
- 不增加通用宣传文案、虚构指标或产品能力。
- 操作提示保持简短：`拖动旋转 · 滚轮或双指缩放`。

## 7. 响应式与可访问性

- 验证宽度：320、375、414、768和1440像素。
- 所有按钮和滑杆可使用键盘操作并具有可见焦点。
- 滑杆提供中文标签、当前数值和合上/分开语义。
- 3D画布不能阻止页面正常纵向滚动；手机端仅在明确触摸模型后接管旋转手势。
- iframe必须有 `title`，并提供无法加载时的替代入口。

## 8. 验收标准

- 原作品集12页数量与顺序无变化。
- 3D模型可在PC和手机浏览器中旋转、缩放、复位。
- 分开/合上滑杆可以连续控制保留零件的位置。
- UI原型的主要推荐路径可在嵌入区完成。
- GitHub Pages项目子路径下的模型、原型图片、CSS和脚本均能正确加载。
- 320—1440像素无横向溢出。
- 构建通过，浏览器控制台无未处理错误。

## 9. 明确不做

- 不修改原 `.3dm` 文件。
- 不把3D模型加载设为进入项目页的前置条件。
- 不接入真实传感器、定位、医疗服务或后端数据库。
- 本轮不为 NightCare、租前眼或出去晃晃制作新的交互区。
